# Approach

Compute the number of levels along the leftmost and rightmost paths as `leftH` and `rightH`, respectively.

- If they are equal, all levels of the complete binary tree are full, so return `2^rightH-1` directly.
- If they differ, then `leftH = rightH+1`. In this case, `total = 2^rightH` is the capacity of the last level, and the levels above it contain `total-1` nodes.

Nodes on the last level occupy consecutive positions from left to right. Therefore, use binary search to find the last existing position, then add the number of nodes in the levels above.

# Correctness

Number the root as `1` and the left and right children of node `v` as `2v` and `2v+1`, respectively. The node number at position `mid` on the last level is:

`mid + total - 1`

`FindRoute` traces back from this number toward the root:

- `lvlTotal` represents the starting node number of the current level.
- `(idNum-lvlTotal+1)%2` determines whether the position within the level is odd or even: `1` indicates a left child, and `0` indicates a right child.
- Integer-divide both the node number and the level's starting node number by `2` to move to the parent's level.

The resulting path is ordered from bottom to top, so `Check` reads it in reverse and follows it from the root to the target position. All nodes above the last level exist, so only the final step can reach a null node.

When binary search begins, the last level is not full. Therefore, position `1` must exist, and position `total` must not exist. The code always maintains the following invariant:

- `left` points to an existing position.
- `right` points to a nonexistent position.

After checking `mid`, move the corresponding boundary inward based on whether the node exists. Since node existence is monotonic from left to right, when `right-left == 1`, `left` is the last existing position, which is also the number of nodes on the last level.

Therefore, `total-1+left` gives exactly the number of nodes in the entire tree.

# Complexity

Let the number of nodes be `n`:

- Time complexity: `O(log² n)` in the worst case. Binary search performs `O(log n)` iterations, and generating the path and checking the node take `O(log n)` per iteration.
- Space complexity: `O(log n)` for the path list generated by `FindRoute`.
